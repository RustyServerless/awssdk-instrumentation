## [0.3.0]

### Added

- Added the `extra_init_code` option to the `make_lambda_runtime!` macro, allowing to pass arbitrary code to be executed just before launching the lambda runtime.
- Added the `sdk_client_interceptor` option to the `make_lambda_runtime!` macro, allowing to explicitly choose the interceptor instead of relying on the default one.
- Added the `lambda_layer_instrumentor` option to the `make_lambda_runtime!` macro, allowing to explicitly choose the instrumentor instead of relying on the default one.
- The tracing-backend AWS SDK client interceptor now adds the `rpc.system.name` attribute (Semantic Convention) in addition to the already present (deprecated) `rpc.system`
- The `xray-no-lambda-node-nesting` feature controls if Lambda X-Ray segment should be emitted as nested inside the Lambda function segment or not. Enable the feature to keep the segment separate.
- Now publicly re-export `aws_smithy_runtime_api::{box_error::BoxError, client::interceptors::context, http}` under the `awssdk-instrumentation::interceptor` module to ease implementation of custom SDK client interceptors.w

### Changed

- Bumped MSRV to 1.88
- Switching to opentelemetry-aws (instead of the tmp crate I published) following the release of v0.21 with all my PRs merged
- Removed the `semconv_experimental` feature of `opentelemetry-semantic-conventions`
- When looking for the tracing aws_sdk operation span, added a more precise target matching condition: `aws_sdk_*::operation::*` instead of `*::operation::*`
- Made the `tracing_subscriber` crate a mandatory dependency, but stripping it of un-needed features unless our `tracing-backend` feature is enabled
- The X-Ray exporter is now configured to export all the attributes as Metadata by default, aligning with ADOTv2 behavior. The `XRAY_METADATA` env var no longer accept the "all" value (as it is now the default behavior). If `XRAY_METADATA` is defined, only listed attributes will be pushed. An empty `XRAY_METADATA` will prevent the default export-all behavior. Note that `XRAY_ANNOTATIONS` usage is unchanged.
- By default, the X-Ray segment emitted for a Lambda function is now nested under the AWS::Lambda::Function node pushed by the service.
- Changed the top-level span name generated by the Lambda Tracing Layer to `Invocation` on both `tracing-backend` and `otel-backend`
- The default `OTelFaasTrigger` variant is now Http (instead of DataSource), aligning with the default value already chosen by the `make_lambda_runtime!` macro.

### Removed

- Removed the `env` module entirely and instead rely on the new Resource Detectors of the `opentelemetry-aws` crate. The public functions `env::default_resource()`, `env::lambda::lambda_resource()`, `env::ecs::ecs_resource()`, `env::eks::eks_resource()` and `env::ec2::ec2_resource()` are gone with it.
- Removed the custom defined `RPC_SYSTEM_NAME` and `DB_SYSTEM_NAME` consts and uses the ones of `opentelemetry-semantic-conventions`
- Removed the `cloud.account.id` attribute from the Lambda Tracing layer as it is covered by the `opentelemetry-aws` Resource Detector

### Fixed

- Fixed the OTel backend bug that would produce a handler span containing only the xray_trace_id, without any of the Lambda attributes
- Fixed the `otel-backend` bug that could not find the SDK operation span when the `tracing-backend` feature was disabled.
- For Lambda, added the `service.name` attribute with the function name as its value, pending addition to the Lambda resource detector.

### Breaking changes

- The `env` module and all its public functions have been removed. Resource detection is now delegated to the Resource Detectors of the `opentelemetry-aws` crate, and every enabled `env-*` feature now pulls in that crate.
- The `interceptor::DB_SYSTEM_NAME` and `interceptor::RPC_SYSTEM_NAME` constants have been removed. Use `opentelemetry_semantic_conventions::attribute::DB_SYSTEM_NAME` and `::RPC_SYSTEM_NAME` instead.
- `tracing-subscriber` is now a mandatory dependency. `default_telemetry_init()` now always installs a `tracing` subscriber implementing `LookupSpan`, including when only `otel-backend` is enabled, because the interceptor needs it to locate the AWS SDK operation span. Users composing their own subscriber stack with `default_tracer_provider()` must install such a subscriber themselves.
- The top-level span emitted by the Lambda Tracing Layer is now named `Invocation` on both backends (it used to be named after `AWS_LAMBDA_FUNCTION_NAME` on `otel-backend` and `Lambda runtime invoke` on `tracing-backend`) and now has `internal` kind by default instead of `server`. Enable the new `xray-no-lambda-node-nesting` feature to get the previous `server` kind back.
- The `cloud.account.id` attribute is no longer set on the Lambda invocation span. It is now provided as a resource attribute by the `opentelemetry-aws` Lambda Resource Detector.
- The `XRAY_METADATA` environment variable no longer accepts the `all` value, because exporting all attributes as metadata is now the default. Setting `XRAY_METADATA` to an empty value prevents the default export-all behavior. `XRAY_ANNOTATIONS` is unchanged.
- The default `OTelFaasTrigger` variant is now Http (instead of DataSource). Breaking if your code uses `TracingLayer::new()` without `.with_trigger(...)`.

## [0.2.0] - 2026-04-27

Re-export every external crate that appears in the public API so that users no longer have to add the same dependencies to their own `Cargo.toml` simply to make this crate's macros and traits compile.

### Added

- Crate-root re-exports of `aws_config`, `aws_smithy_runtime_api`, `aws_smithy_types`, `opentelemetry`, `opentelemetry_sdk`, and `opentelemetry_semantic_conventions`.
- Crate-root re-exports of `tracing`, `tracing_subscriber`, and `tracing_opentelemetry`, gated on the `tracing-backend` feature.
- `lambda::LambdaError` and `lambda::LambdaEvent` convenience aliases for `lambda_runtime::Error` and `lambda_runtime::LambdaEvent`.
- The `lambda` module now publicly re-exports `lambda_runtime` (previously `#[doc(hidden)]`).
- New "Re-exported crates" section in the crate-level documentation.

### Changed

- `aws-config` moved from `dev-dependencies` to `dependencies`, with the `behavior-version-latest` feature pinned. The `make_lambda_runtime!` and `aws_sdk_config_provider!` macros now reference `aws-config` through the crate's re-export, so users no longer need to depend on `aws-config` directly.
- `opentelemetry_sdk` is now re-exported at the crate root rather than only inside the `lambda` module, matching its use in non-Lambda public APIs.
- Documentation examples updated to use the convenience aliases `LambdaError` / `LambdaEvent` and the re-exported `lambda_runtime` path.

### Notes

- Users still need to declare these as direct dependencies: the `aws-sdk-*` service crates they use, `tokio` (the `#[tokio::main]` proc-macro emitted by `make_lambda_runtime!` resolves `tokio` by absolute path), and `serde_json` for typical Lambda event types.

## [0.1.0] - 2026-03-30 [YANKED]

Initial public release.

### Added

- SDK interceptor (`DefaultInterceptor`) implementing the AWS SDK `Intercept` trait — automatically attaches OpenTelemetry semantic-convention attributes to every AWS SDK call (region, operation, HTTP status, request ID, service-specific attributes).
- `DefaultExtractor` extraction pipeline with per-service dispatch and support for user-registered hooks and custom `AttributeExtractor` implementations.
- `ServiceFilter` for scoping closure hooks to specific services or operations.
- `SpanWrite` trait abstracting span attribute writes across backends.
- `tracing-backend` (default) — writes span attributes via `tracing::Span` + `tracing-opentelemetry`.
- `otel-backend` — manages OTel spans directly without `tracing`.
- Compile-time enforcement that at least one backend is enabled.
- `TracingLayer` Tower layer (`env-lambda`) — creates a per-invocation span, propagates X-Ray trace context, tracks cold-starts, and flushes the exporter after each invocation.
- `make_lambda_runtime!` macro — generates `main()`, telemetry initialisation, SDK client singletons, and Tower layer setup in a single call.
- Lambda resource detector (`env-lambda`).
- `default_resource()` probing Lambda, ECS, EKS, and EC2 environments with fallback to minimal `cloud.provider = aws`.
- ECS resource detector (`env-ecs`) — reads container metadata endpoint.
- EKS resource detector (`env-eks`) — reads Kubernetes service account + IMDSv2.
- EC2 resource detector (`env-ec2`) — reads IMDSv2.
- DynamoDB attribute extractor (`extract-dynamodb`, default) — table name, consumed capacity, etc.
- S3 attribute extractor (`extract-s3`) — bucket name, key, etc.
- SQS attribute extractor (`extract-sqs`) — queue URL, message ID, etc.
- X-Ray ID generator and daemon exporter (`export-xray`, default) via `opentelemetry-aws`. Re-exports `opentelemetry_aws` at the crate root, making its X-Ray propagator available for usage.
- `XRAY_ANNOTATIONS` and `XRAY_METADATA` environment variables for controlling X-Ray segment mapping.
- `default_telemetry_init()` — one-call setup: builds a `SdkTracerProvider` with detected resource, X-Ray ID generator, batch exporter, global provider registration, and `tracing-subscriber` with JSON console layer and OTel bridge.
- `default_tracer_provider()` for building the provider without subscriber setup.
- `ParentBased(AlwaysOff)` default sampler on Lambda (respects X-Ray sampling); `ParentBased(AlwaysOn)` outside Lambda.
